# Архитектура проекта

## 1. Основной принцип

Сайт не состоит из отдельных дизайнов для отдельных правителей.

Он состоит из пяти независимых систем:

1. **Product Core** — неизменяемая UX- и компонентная ДНК сайта.
2. **Historical Visual State Engine** — исторически меняющаяся визуальная оболочка.
3. **Module System** — строительные блоки страницы правителя.
4. **Content Model** — исторические данные, не привязанные к конкретной вёрстке.
5. **Timeline + Map subsystems** — отдельные движки хронологии и территории.

## 2. Product Core

Core отвечает за:

- responsive grid;
- базовый spacing scale;
- доступность;
- навигационную модель;
- минимальные размеры интерактивных зон;
- смысловую иерархию;
- базовые компонентные контракты;
- loading/error/empty conventions.

Historical Visual State **не имеет права** произвольно переписывать эти правила.

## 3. Historical Visual State

Вместо схемы `era = одна тема` состояние собирается из слоёв:

`Core → cultural/polity layer → period layer → reign layer → rupture/context layer`

Пример:

`Core + Empire + Late XVIII + Catherine II`

или:

`Core + Revolution + 1917 rupture + Provisional Government`

или:

`Core + USSR + Stalin period + Stalin reign`

Каждый слой содержит только разрешённые override-токены.

## 4. Почему слои, а не одна тема

Это позволяет:

- сохранить родство Екатерины II, Павла I и Александра I;
- одновременно сделать их ощутимо разными;
- сделать 1917 год визуальным разрывом;
- сильно развести Ленина и Сталина, не создавая второй сайт;
- отдельно настроить Новое время;
- плавно интерполировать визуальные параметры между соседними правлениями.

## 5. Границы ответственности

`content/` не знает, как выглядит карточка.

`modules/` не знает, какой сейчас правитель, кроме полученных данных.

`historical-state/` не знает содержимое исторического текста.

`map/` не решает, как устроена страница.

`timeline/` управляет хронологическим положением и переходами, но не содержит визуальные значения напрямую.

## 6. Главный запрет

Нельзя создавать `CatherineCard`, `StalinButton`, `ImperialTimeline` и другие компоненты, в которых исторический период зашит в имя и логику компонента.

Правильно:

`EventCard + Historical Visual State`.

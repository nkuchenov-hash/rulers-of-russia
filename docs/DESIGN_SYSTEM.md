# Core Design System

## Что всегда едино

- смысл компонентов;
- базовая сетка;
- responsive breakpoints;
- базовый вертикальный ритм;
- интерактивная модель;
- accessibility contract;
- структура навигации;
- правила состояния hover/focus/disabled;
- семантика типографических ролей.

## Семантические токены

Компоненты не используют исторические названия и не должны знать конкретные HEX-цвета.

Компонент просит:

- `--page-bg`
- `--surface-primary`
- `--surface-elevated`
- `--text-primary`
- `--text-muted`
- `--accent-primary`
- `--accent-secondary`
- `--border-emphasis`
- `--map-land`
- `--map-water`
- `--display-font`
- `--body-font`
- `--display-tracking`
- `--surface-radius`
- `--shadow-character`
- `--texture-opacity`

Historical Visual State задаёт значения этих ручек.

## Что историческое состояние МОЖЕТ менять

- цветовую атмосферу;
- материалы и поверхности;
- display typography;
- декоративный tracking;
- характер рамок;
- допустимый диапазон радиусов;
- тип/интенсивность текстур;
- художественную обработку изображений;
- картографический treatment;
- ambient motion;
- орнаментальный язык;
- композиционный акцент в пределах разрешённых слотов модуля.

## Что историческое состояние НЕ МОЖЕТ ломать

- читаемость body text;
- минимальные размеры touch target;
- focus state;
- порядок контента;
- breakpoint logic;
- основную навигацию;
- доступность;
- значение компонента;
- произвольную смену размеров UI только ради декора.

## Правило историчности

Исторические источники переводятся в современный UI-язык. Нельзя буквально превращать интерфейс в старую рукопись, плакат, газету, орден, мраморную табличку или советский стенд.

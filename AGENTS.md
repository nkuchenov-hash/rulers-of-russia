# Правители России — правила работы для AI-разработчика

> Навигационный файл. Не заменяет документацию продукта, архитектуры или исторических данных. Перед изменениями проверить фактический код и ветку.

## Источники истины

1. `docs/ARCHITECTURE.md` — пять независимых систем, границы ответственности.
2. `docs/DESIGN_SYSTEM.md`, `docs/GENERIC_CORE_RULE.md`, `docs/LAYOUT_CONTRACT.md` — неизменяемый Product Core и правила сетки.
3. `docs/HISTORICAL_VISUAL_STATE.md` — визуальная историческая оболочка, независимая от семантических модулей.
4. `docs/MODULE_SYSTEM.md` — назначение и структура модулей.
5. `docs/CONTENT_SCHEMA.md`, `docs/MAP_ENGINE.md`, `docs/TIMELINE_ENGINE.md` — контракты данных и движков.
6. `docs/DECISIONS.md` — принятые решения; `docs/TEST_LAB.md` — каноническая живая тестовая страница.
7. `docs/PROJECT_STRUCTURE.md` — только обзор папок, не полный перечень файлов.
8. `docs/DOCUMENTATION_PARITY_2026-10-17.md` — снимок подтверждённых пробелов, **не** новая архитектура.

## Код: куда идти в первую очередь

- `src/app/page.tsx` → `src/components/core-system/CoreDesignSystemSkeleton`: главная страница / каркас.
- `src/app/rulers/[slug]/page.tsx` → `src/components/RulerPage`, `src/content/rulers/`: реальные страницы правителей и контент.
- `src/design-system/`, `src/historical-state/`: компоненты и исторические визуальные значения.
- `src/modules/`: семантические модули и их контракты.
- `src/app/lab/page.tsx`: тестовый маршрут; проверить на соответствие `docs/TEST_LAB.md`.
- `scripts/validate-history-core.mjs`, `public/data/history-core/`: источник и валидация исторического датасета.
- `src/app/territory/`: сложная карта/территории; перед редактированием изучить фактических потребителей геоданных.

## Правила изменений

- Сначала читать относящиеся к задаче договорённости и исходники. Менять один владеющий модуль за раз.
- Не копировать core-компоненты и не вводить отдельные палитры внутри страниц правителей.
- Не подменять географическую достоверность визуальным оформлением; не нарушать хронологическую модель перекрывающихся властей.
- Не переписывать или удалять исходные исторические документы, атрибуцию, геоданные, генерируемые файлы и аварийные точки без доказанного отсутствия потребителей.
- Не менять production, workflows или структуры данных в рамках documentation-only работы.
- Если документация и код расходятся, проверить факты и зафиксировать конкретный путь/символ перед исправлением; не объявлять код ошибочным только по старому описанию.

## Проверка перед релизом

В рабочем checkout проверить применимые команды из `package.json`: `npm run typecheck`, `npm run build`, `npm run validate:history`, при географических изменениях — `npm run validate:history-geometry` и профильные скрипты. **Внимание:** `validate:history` вызывает подготовку/генерацию данных; до запуска проверить побочные эффекты и сохранить diff.

Без исполнения этих команд и проверки `/lab/` не заявлять, что сборка/геометрия/UX прошли проверку. Фиксировать SHA, команды и результаты в отчёте.
